injection-audit / field note

The report that survives being handed over

By Elena Brandt · 23 November 2026

A finding is easy to produce and hard to defend. The awkward moment is three months later, when somebody asks which version of the file was scanned, and all you have is a screenshot with a line number.

I built injection-audit to make the opposite of a dashboard: one file that carries its own evidence.

What a run actually produced

report      : IA-20261123T000000Z-904ad9a57c9d
delivered   : 2026-11-23
repo digest : 904ad9a57c9d7b5c3405da8e8c939257b63d200a44722f9ccd7e6e43a291f8d0
analysed    : 2 files
findings    : 2

Both findings were CWE-78: os.system("grep -n " + sys.argv[1]) in a Python file and eval "echo $name" in a shell script. Ordinary bugs. The part worth writing about is the container they arrive in.

Each numbered finding carries a rule id, a CWE class, the quoted source line, and a SHA-256 hash for every analysed file. The whole tree gets a digest. A coverage block states what was skipped and why. An HMAC-SHA256 signature covers the canonical JSON payload; the report records only the SHA-256 id of the signing key, never the key itself.

Why sign the artefact and not the claim

A client can verify the document has not been edited since it was signed, and check the file hashes against the tree, without installing my scanner and without receiving my source code. That is the entire product. The scanner is free and boring; the dated, verifiable record is what a consultancy can actually file.

$ python -m injection_audit verify report.json --key-file ia.key
signature valid for key sha256:da466a4a6b0fa977df6e3ed163f034167900ac97b85fe3f4d834f4531337ef1d

Pin the clock with --now and two scans of the same tree are byte-identical, which matters when a client asks for a re-issued copy of a report from last quarter.

Limits, in the document itself

Taint tracking is intra-file and intra-function. An argv token is only called CWE-88 when the hazard is provable from literals. Unsupported languages, parse failures and oversized files are listed as skipped, never silently dropped.

This is not a compliance certificate, a penetration test, or a guarantee. It records dated evidence of findings in the analysed files only.
